## ১. প্রকল্পের ভূমিকা ও উদ্দেশ্য (Overview)
"গ্রামীণ কল্যাণ কেরানীগঞ্জ" অ্যাপ্লিকেশনটি কেরানীগঞ্জ অঞ্চলের **১১টি গ্রামীণ কল্যাণ স্বাস্থ্য কেন্দ্রের** আর্থিক ও প্রশাসনিক কার্যক্রম ডিজিটালাইজড ও নিরীক্ষিত করার উদ্দেশ্যে তৈরি। 

অ্যাপ্লিকেশনটির প্রধান লক্ষ্য:
- ১১টি কেন্দ্রের দৈনিক ও সাপ্তাহিক আয়, ব্যয় ও রোগী সেবা নির্ভুলভাবে সংরক্ষণ।
- স্বয়ংক্রিয় রিকনসিলিয়েশন ও অমিল (Discrepancy) চিহ্নিতকরণ।
- অবচয়সহ কস্ট রিকভারি (Cost Recovery %) নির্ভুল গণনা।
- মাসিক স্প্রেডশীট (কলাম A হতে J) লক্ষ্যমাত্রা ও অগ্রগতির রিয়েল-টাইম হিসাব।
- অফলাইন-ফার্স্ট রুম ডাটাবেজ ও ক্লাউড ফায়ারস্টোর সিঙ্ক।
- প্রতিটি সংশোধন ও অনুমোদনের স্থায়ী অডিট ট্রেইল (Audit Log)।
- এসএমএস কম্পোজার ইন্টিগ্রেশন ও এক্সেল/পিডিএফ রিপোর্ট এক্সপোর্ট।

## ৩. হিসাবরক্ষণ নীতি ও গাণিতিক সূত্র (Accounting Policies & Formulas)

### ক. কস্ট রিকভারি হার (Cost Recovery %)
$$\text{Cost Recovery (\%)} = \left( \frac{\text{মোট আয় (Total Income)}}{\text{মোট ব্যয় অবচয়সহ (Total Expense Incl. Depreciation)}} \right) \times 100$$

- **অবচয় সংক্রান্ত কড়াকড়ি:** দৈনিক ফর্মের ফিল্ড ৮ এবং সাপ্তাহিক ফর্মের ফিল্ড ৬-এ ইতোমধ্যে অবচয় অন্তর্ভুক্ত রয়েছে। তাই কোনো অবস্থাতেই দ্বিতীয়বার অবচয় যোগ করা যাবে না।
- **ফিল্ড ৫ (ঔষধ ও ল্যাব খরচ):** এটি একটি পৃথক রিপোর্টকৃত ব্যয় উপাদান; এটি ফিল্ড ৮-এর সাথে স্বয়ংক্রিয়ভাবে যুক্ত হবে না। যদি ফিল্ড ৫ ফিল্ড ৮-এর চেয়ে বেশি হয়, সিস্টেমে একটি অডিট ওয়ার্নিং দৃশ্যমান হবে।
- **ব্যয় শূন্যের বিশেষ শর্ত:**
  - যদি ব্যয় = ০ এবং আয় > ০: সিস্টেমে **"ব্যয় নথিভুক্ত নয় / নির্ভরযোগ্যভাবে গণনা সম্ভব নয়"** প্রদর্শিত হবে (অসীম বা ইনফিনিটি প্রদর্শিত হবে না)।
  - যদি ব্যয় = ০ এবং আয় = ০: সিস্টেমে **"কোনো আর্থিক লেনদেন নেই"** প্রদর্শিত হবে।

### খ. সাপ্তাহিক রিকনসিলিয়েশন ও ভ্যালিডেশন
- $\text{কেন্দ্র আয়} = 3.1 + 3.2 + 3.3 + 3.4 + 3.5$
- $\text{ক্যাম্প আয়} = 4.1 + 4.2 + 4.3 + 4.4 + 4.5$
- $\text{গণনাকৃত মোট সাপ্তাহিক আয়} = \text{কেন্দ্র আয়} + \text{ক্যাম্প আয়}$
- $\text{ব্যবধান (Discrepancy)} = \text{দাখিলকৃত মোট আয় (ফিল্ড ৫)} - \text{গণনাকৃত মোট সাপ্তাহিক আয়}$
  - ব্যবধান = ০ হলে রিপোর্টটি `VALIDATED` হবে।
  - ব্যবধান $\neq$ ০ হলে রিপোর্টটি স্বয়ংক্রিয়ভাবে `PENDING_VERIFICATION` হবে এবং নিশ্চিত আয় হিসেবে গণনা থেকে সাময়িক বিরত রাখা হবে। এডমিন বা হিসাবরক্ষক সুনির্দিষ্ট কারণ ও অডিট ট্রেইল সহ এটি সংশোধন করতে পারবেন।

### গ. অফিশিয়াল টেস্ট ডাটা যাচাই (Verified Test Cases)
1. **টঙ্গীবাড়ী স্বাস্থ্য কেন্দ্র:**
   - কেন্দ্র আয়: $440 + 2947 + 1520 + 0 + 620 = 5527$
   - ক্যাম্প আয়: $600 + 3483 + 1180 + 0 + 320 = 5583$
   - মোট সাপ্তাহিক আয়: $11,110$ (সাপ্তাহিক ব্যয়: ১,৭০০) $\rightarrow$ **VALIDATED**
2. **মালখানগর স্বাস্থ্য কেন্দ্র:**
   - কেন্দ্র আয়: $3500 + 6163 + 1200 + 0 + 560 = 11423$
   - ক্যাম্প আয়: $4300 + 14283 + 9296 + 3300 + 1270 = 32449$
   - মোট সাপ্তাহিক আয়: $43,872$ (সাপ্তাহিক ব্যয়: ১৭,০০০) $\rightarrow$ **VALIDATED**

### ঘ. মাসিক স্প্রেডশীট হিসাব (Columns A to J)
- **A.** স্বাস্থ্য কেন্দ্র (Health Centre)
- **B.** মাসিক কার্যদিবস (Working Days)
- **C.** দৈনিক আয়ের লক্ষ্যমাত্রা (Daily Target)
- **D.** মাসিক আয়ের লক্ষ্যমাত্রা ($D = B \times C$, যদি না এডমিন ম্যানুয়ালি অনুমোদন করেন)
- **E.** আজকের আয় (Current Day Income)
- **F.** অর্জিত আয় ($F = \sum \text{দৈনিক নিশ্চিত আয়}$)
- **G.** আয়ের ঘাটতি ($G = \max(D - F, 0)$)
- **H.** অর্জনের হার ($H = (F / D) \times 100$)
- **J.** অবশিষ্ট কার্যদিবস (Remaining Working Days)
- **I.** বাকি দিনসমূহে প্রয়োজনীয় দৈনিক গড় আয় ($I = \max(D - F, 0) / J$)

## ৫. ক্লাউড ফায়ারস্টোর ও ব্যাকএন্ড কনফিগারেশন গাইড

1. **ফায়ারবেস প্রজেক্ট সেটআপ:**
   - [Firebase Console](https://console.firebase.google.com/) এ গিয়ে একটি নতুন প্রজেক্ট তৈরি করুন।
   - Android অ্যাপ নিবন্ধন করুন:
     - প্যাকেজ নাম: `com.aistudio.gkkeraniganj.bkzpt`
   - কনসোল থেকে `google-services.json` ডাউনলোড করে প্রজেক্টের `app/` ফোল্ডারে রাখুন।

2. **ফায়ারস্টোর ডাটাবেজ তৈরি ও রুলস ডিপ্লয়:**
   - প্রজেক্টের রুট ডিরেক্টরিতে প্রস্তুতকৃত `firestore.rules` ফাইলটি সরাসরি ফায়ারবেস কনসোলে পেস্ট করুন অথবা ফায়ারবেস সিএলআই দিয়ে ডিপ্লয় করুন:
   ```bash
   firebase deploy --only firestore:rules
   ```

3. **অথেন্টিকেশন অ্যাক্টিভেশন:**
   - Authentication মেনুতে গিয়ে **Google Sign-In** এবং **Email/Password** সক্রিয় করুন।

## ৬. অ্যান্ড্রয়েড এপিকে (APK) তৈরি ও ইনস্টলেশন নির্দেশিকা

### ক. টেস্ট ও কম্পাইলেশন যাচাই
টার্মিনাল থেকে টেস্ট ও বিল্ড যাচাই করতে:
```bash
gradle testDebugUnitTest
```

### খ. ডিবাগ এপিকে (Debug APK) তৈরি
ফোন বা এমুলেটরে সরাসরি রান করার জন্য ডিবাগ এপিকে বিল্ড করুন:
```bash
gradle :app:assembleDebug
```
বিল্ড সম্পন্ন হলে এপিকে ফাইলটি এই লোকেশনে পাওয়া যাবে:
`app/build/outputs/apk/debug/app-debug.apk`

### গ. অ্যান্ড্রয়েড ফোনে ইনস্টল করার নিয়ম
1. ইউএসবি কেবল দিয়ে আপনার অ্যান্ড্রয়েড ফোন পিসির সাথে সংযুক্ত করুন।
2. ফোনে **Developer Options** চালু করে **USB Debugging** অন করুন।
3. কমান্ড চালান:
```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```
*(অথবা APK ফাইলটি সরাসরি Google Drive বা ব্লুটুথ দিয়ে ফোনে পাঠিয়ে ইনস্টল করুন।)*

### ঘ. রিলিজ এপিকে বা বান্ডেল তৈরি (Play Store / Production)
```bash
gradle :app:assembleRelease
```
অথবা গুগল প্লে স্টোরের জন্য এএবি (AAB):
```bash
gradle :app:bundleRelease
```
বিল্ড আউটপুট:
`app/build/outputs/bundle/release/app-release.aab`
